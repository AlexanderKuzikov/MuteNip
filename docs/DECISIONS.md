# DECISIONS — MuteNip

## 001: Отдельное приложение, тонкий exe и внешние ffmpeg/ffprobe (2026-10-29)

**Статус:** принято

**Контекст:** нужна утилита для удаления звука из локальных видео. MuteNip задуман отдельно от ClipNip, но с прицелом на последующее объединение. В ClipNip уже накоплен опыт: встроенные PE-бинарники раздувают exe и дают ложные срабатывания антивирусов (ADR ClipNip 011/012), а парсинг CLI-вывода хрупок.

**Решение:**

- Отдельный проект на Go + WebView2, UI через loopback HTTP, как в ClipNip.
- Ядро (`mute/`) не зависит от UI и HTTP: скан, проба, ремукс, прогресс. При объединении переносится пакетом.
- `ffmpeg.exe` и `ffprobe.exe` не вшиваются. Порядок поиска: рядом с exe → `%LOCALAPPDATA%\clipnip\bin` → `PATH`.
- exe ~7.5 MB, внутри нет ни одного PE.

**Альтернативы:** встроить ffmpeg (+38 MB gzip, паттерн «PE внутри PE»); вызвать системный ffmpeg без ffprobe и парсить stderr — отвергнуто, ffprobe даёт стабильный JSON.

**Trade-offs:** без ffmpeg/ffprobe приложение не работает и показывает баннер; при объединении с ClipNip путь к инструментам уже совпадает с кэшем ClipNip. `ffmpeg` может взяться из кэша ClipNip, а `ffprobe` — из PATH; версии совместимы по контейнерам.

## 002: Только stream copy, без перекодирования (2026-10-29)

**Статус:** принято

**Контекст:** удаление аудиодорожки не требует декодирования видео. Перекодирование меняло бы качество и длительность операции.

**Решение:** ремукс командой

```bash
ffmpeg -hide_banner -nostdin -y -i input \
  -map 0 -map -0:a -c copy \
  -progress pipe:1 -nostats -loglevel error output
```

`-map 0` сохраняет видео, субтитры, главы, вложения; `-map -0:a` убирает все аудиопотоки; `-c copy` копирует данные без потерь.

**Альтернативы:** `-an` без явного маппинга — работает, но менее наглядно и хуже контролирует нестандартные потоки; полное перекодирование — отвергнуто как потеря качества и времени.

**Trade-offs:** контейнеры и потоки, которые нельзя скопировать, завершаются ошибкой по файлу. Перекодировать молча нельзя: это меняет обещание «без потери качества». Проверено на mp4 (h264/aac), mkv (h264/aac + subrip) и mov без звука; субтитры mkv сохраняются.

## 003: Копия `_na` по умолчанию, замена с безвозвратным удалением — по галочке (2026-10-29)

**Статус:** принято

**Контекст:** пользователю нужны оба сценария: оставить исходники или освободить место. Удаление необратимо.

**Решение:**

- По умолчанию результат пишется рядом как `name_na.ext`; исходник не трогается. Если такой файл уже есть — ошибка, без перезаписи.
- Галочка «Удалить исходники» включает замену. Перед стартом показывается отдельное окно с числом файлов и суммарным размером.
- Порядок замены: ремукс во временный файл рядом → проверка ffprobe (видео есть, аудио нет, размер > 0) → исходник переименовывается в `name.mutenip-old-*.ext` → временный файл переименовывается в исходное имя → старая копия удаляется.
- Если проверка не прошла, исходник остаётся нетронутым; ошибка уходит в строку результата.
- Корзина не используется — сознательный выбор пользователя.

**Проверено:** замена mkv сохранила субтитры и удалила аудио; при отмене посреди обработки исходник остался с аудио, временных файлов не осталось.

**Trade-offs:** нужен свободный объём примерно на размер выбранного файла даже при удалении; при сбое между двумя переименованиями исходник окажется под именем `.mutenip-old-*` — окно крошечное, но восстановление ручное. Защита от сбойного результата есть, от ошибки пользователя в подтверждении — нет.

## 004: Экономия считается оценкой, а не точным размером дорожки (2026-10-29)

**Статус:** принято

**Контекст:** колонка «экономия» нужна до обработки, чтобы выбирать файлы. Точный размер аудио можно получить суммой размеров пакетов, но это чтение всего контейнера на каждый файл — скан папки стал бы минутами.

**Решение:** оценка `битрейт аудио × длительность` по данным ffprobe. Если битрейт не указан, берётся типовой для кодека (aac 128k, mp3 192k, opus 96k, ac3 384k, flac 900k и т. д.). В UI цифра помечена `≈`. После обработки показывается фактическая разница «до минус после».

**Альтернативы:** точная сумма пакетов при скане — отвергнута по времени; не показывать экономию вообще — противоречит задаче выбора.

**Trade-offs:** VBR-дорожки (opus, часть aac) дают заметную ошибку. Это ориентир, а не бухгалтерия; фактическая цифра есть в итогах. Проверено: оценка aac 125867 бит/с × 6 с ≈ 94 КБ, факт — 98.5 КБ.

## 005: Постоянная панель навигации вместо модального выбора папки (2026-10-29)

**Статус:** принято (заменяет первое решение с `SHBrowseForFolderW`)

**Контекст:** первая версия выбирала папку нативным модальным диалогом. Пользователь попросил постоянную панель навигации с удобным выбором файлов. Модальный диалог скрывает дерево, не показывает соседние папки и не даёт переключаться между корнями на ходу.

**Решение:**

- Слева постоянно висит дерево: диски → папки. Дети загружаются лениво через `GET /api/fs/list?path=…`; список дисков — `GET /api/fs/drives` (локальные, съёмные, CD, RAM; сетевые отсекаются по типу).
- Клик по папке вне текущего корня делает её корнем сканирования; скан стартует сразу, предыдущий скан отменяется.
- Внутри корня клик по папке переключает список на её прямые файлы; крошки возвращают наверх, корневой узел показывает все файлы рекурсивно.
- Чекбоксы папок внутри корня выбирают все подходящие файлы поддерева (tri-state: все / часть / ничего). Счётчик — число файлов со звуком.
- Поиск работает в пределах текущего списка; сортировка — по имени, длительности, размеру, экономии.
- Выбранный корень подсвечивается и прокручивается в видимую область; кнопка «обновить» перечитывает дерево.
- Модальный диалог и `shelldlg.go` удалены.

**Trade-offs:** клик по папке сразу запускает скан — на огромной папке это может быть долго, отмена есть. Дерево кэширует содержимое папок до «обновить». Список дисков на машине с облачными томами длинный (18 букв). Клик по диску только раскрывает его, а не сканирует корень диска — защита от случайного скана всего тома.

## 006: Иконка через .ico и rsrc.syso (2026-10-29)

**Статус:** принято

**Контекст:** WebView2 не наследует иконку exe в окно и панель задач. Без ресурса exe получает стандартную иконку.

**Решение:**

- Исходник — `icon/mutenip.svg`; `icon/mutenip.ico` содержит размеры 16/24/32/48/64/128/256.
- Ресурс вшивается через `rsrc.syso` (`rsrc -ico icon/mutenip.ico -o rsrc.syso`), файл закоммичен — сборка не требует установленного rsrc.
- При старте окна иконка ресурса #1 ставится через `WM_SETICON` для big/small, как в ClipNip.

**Проверено:** `ExtractAssociatedIcon` достаёт иконку 32×32 из собранного exe; лог запущенного окна пишет `window icon: set`; иконка видна в заголовке.

**Trade-offs:** при смене иконки нужно перегенерировать `.ico` и `rsrc.syso`; исходник SVG и команда есть в README/AGENTS.

## 007: Операционные решения — конфиг, один экземпляр, headless (2026-10-29)

**Статус:** принято

**Решение:**

- Последняя папка хранится в `%LOCALAPPDATA%\MuteNip\config.json` и автоматически сканируется при старте. Сканирование read-only, поэтому автозапуск безопасен.
- Именованный mutex `Local\MuteNip.SingleInstance`: два окна не должны одновременно заменять или удалять файлы.
- Headless-режим (`MUTENIP_HEADLESS=1`, `MUTENIP_PORT`) и переопределение каталога данных (`MUTENIP_DATA`) используются для интеграционных проверок. Тесты не должны писать в реальный конфиг.
- Лог — `%LOCALAPPDATA%\MuteNip\mutenip.log`.
- Ошибки инструментов не фатальны: окно поднимается и показывает баннер, если ffmpeg/ffprobe не найдены.

**Trade-offs:** автозапуск скана на большой последней папке заметен сразу после старта; его можно отменить. `MUTENIP_DATA` не влияет на путь к ffmpeg/ffprobe.
